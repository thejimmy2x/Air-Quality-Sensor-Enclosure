# Sensor Stack Enclosure

Parametric, lidded desk enclosure for a multi-sensor air-quality stack, designed in
Fusion 360 (driven by User Parameters) for FDM printing (PETG/ASA, 0.6 mm nozzle).

## Sensor stack
| Board | Size (mm) | Role |
|---|---|---|
| ESP32-S3-DevKitC-1 | ~70 × 28 × 13 | MCU, heat source, external USB-C |
| PMS5003 | 50 × 38 × 21 | Particulate, fan, needs fresh ambient air |
| SCD40 (Adafruit) | ~26 × 18 × 8 | CO2, heat-sensitive |
| BME680 (Adafruit) | ~25 × 18 × 6 | VOC/T/RH/P, heat-sensitive |
| SGP40 (Adafruit) | ~25 × 18 × 5 | VOC index |

## Design
- **External:** ~155 × 83 × 39 mm. Low, wide slab; hex-honeycomb vents; filleted
  corners; chamfered floating base.
- **Thermal zoning:** hot back (PMS + ESP32) vs. cool front (gas sensors); SCD40
  placed farthest from heat.
- **Airflow:** passive honeycomb venting (front + both sides) for the gas sensors;
  PMS5003 isolated with a dedicated round fan-intake port + exhaust on the back wall.
- **Closure:** screw-down lid, M3 heat-set brass inserts (4 corners).
- **Features:** external USB-C port, status-LED light-pipe, removable carrier tray.

## Components (print each once)
- `export/base.3mf` / `.stl` — outer shell with vents, ports, insert bosses
- `export/tray.3mf` / `.stl` — removable sensor carrier (pockets, PMS/ESP cradles)
- `export/lid.3mf` / `.stl` — screw-down lid
- `export/sensor_enclosure_assembly.step` — full assembly (CAD interchange)

  consolidated script; clearances tuned for a 0.6 mm nozzle (pocket +0.5, tray 0.25,
  lid lip 0.4, M3 insert pilot 4.1 mm).

## Security Notes

This config is published as a working reference, not a hardened
deployment. A few things are intentionally left open — review them
against your own network before flashing.

**No API encryption key.** The `api:` block has no `encryption.key`
set, so ESPHome's native API accepts unauthenticated connections from
anything on the same network. Home Assistant will connect without a
key, but so will anyone else. Generate a key at
https://esphome.io/components/api.html and add it under `api:`.

**No OTA password.** The `ota:` block is unprotected, meaning any host
on the network can push new firmware to the device. Add a `password:`
under `ota:` if that matters to you.

**Unauthenticated web server and metrics.** `web_server:` serves the
device UI on port 80 and `prometheus:` exposes a scrape endpoint, both
without authentication. This is convenient on a trusted VLAN and a
liability anywhere else. Do not port-forward this device or place it
on a network you share with guests. `web_server:` supports an `auth:`
block if you want basic credentials.

**Secrets.** All credentials are referenced via `!secret` and resolve
from a `secrets.yaml` that is not included in this repo. Copy
`secrets.yaml.example` to `secrets.yaml` and fill in your own values.
Note that ESPHome's `.esphome/` build directory contains your compiled
config with secrets substituted in as plaintext — keep it out of any
repo you publish.
